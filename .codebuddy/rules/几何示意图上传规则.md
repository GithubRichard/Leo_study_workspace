# 几何示意图上传规则

本规则补充仓库根目录 `README.md` 与 `.codebuddy/skills/leo-study-assistant/SKILL.md` 中“原题照片不上传”的规定；仅对必要的题目示意图开放例外。

## 核心原则

- **原始作业照片、整页试卷、孩子手写作答仍禁止上传 GitHub。**
- 仅当确认错题或存疑题属于**强依赖图形才能理解题意**的题目时，允许保存必要示意图。
- **优先使用 SVG 文本矢量图按原题关系重绘**；SVG 无法可靠表达或无法确认图形关系时，才考虑裁剪题目中的必要示意图。
- 典型范围：几何图形、几何体示意图，以及确有必要的函数图像、统计图、坐标图等。
- 普通代数题、英语题、纯文字题不上传图片。
- 重绘的 SVG 只是题意辅助图，除非题目明确要求按比例，否则必须注明“按题意重绘，不按比例”。

## SVG 重绘要求

1. 只重绘原题中能够可靠确认的图形关系，不凭猜测补全被遮挡、模糊或无法辨认的部分。
2. 必须逐项核对关键点名、线段、连接关系、平行/垂直/中点等题目明确给出的几何关系，以及必要的数字和文字标注。
3. **阴影是题意的一部分，必须单独核查。** 不能只确认点、线和轮廓正确就认为重绘完成。
4. 涉及阴影面积时，提交前必须明确列出“哪些区域应为阴影、哪些区域应保持白色”，并将 SVG 与原题逐区块对照；尤其检查三角形、重叠区域、补形区域和被线段分割后的子区域。
5. 阴影图还必须与文字解法做一次交叉核验：Markdown 中用于面积加减的区域，应与 SVG 实际标出的阴影/非阴影区域一致；若两者矛盾，禁止提交，先回看原题修正。
6. SVG 中不得加入孩子姓名、学校、班级、手写答案、批改痕迹、二维码或其他无关个人信息。
7. 无法可靠判断阴影边界、点位或图形关系时，不生成“看起来合理”的示意图；改为在 Markdown 中注明“示意图待核实”。

## 裁剪图片处理要求

1. 仅在 SVG 无法可靠重绘且确有必要时使用裁剪图片。
2. 只保留理解题意所必需的印刷示意图及必要的印刷标注。
3. 必须尽量排除孩子姓名、学校、班级、手写答案、批改痕迹、二维码、整页试卷及其他无关个人信息。
4. 如果无法在不泄露上述内容的情况下可靠裁出示意图，则不上传，改为在 Markdown 中用文字描述，并注明图片未归档。
5. 不得以“方便”为理由上传整张原图替代裁剪。

## 仓库位置与命名

示意图统一保存到：

`学科/错题示意图/YYYY-MM-DD/`

文件名优先使用可定位的题号，例如：

- `第20题.svg`
- `第20题-图1.svg`
- `第20题-图2.svg`
- 必须使用裁剪图片时可使用 `第20题.png` 等格式。

若同日存在多个来源导致题号重复，在文件名前加入简短来源标识，避免覆盖。

## 与错题记录关联

- 对应的 `学科/错题解析/YYYY-MM-DD.md` 应使用相对路径引用示意图。
- SVG 示例：`![第20题几何示意图](../错题示意图/2026-10-08/第20题.svg)`。
- 示意图只作为错题理解辅助，不能替代 Markdown 中的必要题干、条件、孩子原答案、正确答案、解题步骤和错因分析。

## 何时保存

- 默认仅对**确认错题或存疑题**中确实依赖图形的题保存示意图。
- 正确题一般不单独保存示意图，除非与同一道确认错题共用图形或用户明确要求保留。
- 用户明确说“不要上传图片/原图”时，仍不得上传原始或裁剪位图；若用户允许文本重绘，可使用不含原始照片内容的 SVG。

## Git 与隐私

- SVG 重绘图及符合要求的裁剪示意图属于学习记录附件，可以提交、推送到 GitHub；它们不是 `学科/原题/` 下的原始资料。
- `学科/原题/` 继续保持 `.gitignore` 保护，原始照片仍只在本地保存。
- 提交前必须再次检查示意图，确认没有整页原题、手写作答或个人信息；SVG 还必须完成几何关系与阴影区域核对。

## 提交前示意图自查清单

- 点名和文字标注是否与原题一致？
- 线段、连接关系和图形包含/相邻关系是否一致？
- 中点、垂直、平行等关键条件是否正确表达？
- **阴影区域是否逐块与原题一致？白色区域是否误填成阴影？阴影是否漏填？**
- SVG 的阴影/白色区域是否与 Markdown 的面积计算对象一致？
- 是否存在为了“画得完整”而自行猜测的内容？
- 是否已排除原始照片、手写内容和个人信息？

任一项无法确认时，不提交该示意图，先标记待核实。

## 执行顺序

涉及此类作业时：读取仓库 `README.md` → 读取 `leo-study-assistant/SKILL.md` → 遵循本补充规则 → 首轮批改 → 有确认错题则按规定二次核查 → 主代理复核 → 判断是否需要示意图 → **优先 SVG 重绘 → 逐项核对几何关系 → 单独核对阴影/白色区域 → 与文字解法交叉核验** → 更新当天错题记录并引用示意图 → 自查 → 提交到 GitHub。
