# Leo_study_workspace

用于保存给 Leo 批改作业、错题解析、强化训练与复习计划的学习资料库。所有内容按学科归档，便于回溯「什么时候错的、错在哪、是否订正、下次练什么」。

**目标不只是保存答案，而是积累有依据的学习记录，在月考、期中考和期末考前，针对反复出错及尚未掌握的知识点安排训练。**

学习记录的关系：**每日错题解析 → 周报归纳 → 专项或考前训练 → 实际复测 → 更新记录**。

> Agent 处理本仓库的学习任务时，应在回答前先读取本 `README.md`，按下述规则处理、归档和上传成果。本文件是工作规范，不是自动运行的程序；用户仍需要求 agent 先读取它。

```text
└── 英语/
    ├── 错题解析/
    ├── 强化训练/
    ├── 周报分析/
    └── 错题周报/                 （历史资料保留，新周报不再写入）
        └── 2026-09-20.md
```

一级目录按**学科**划分；以后新增学科也使用三个标准子目录。空目录以 `.gitkeep` 纳入 Git，不预填虚构学习记录。

| 目录 | 用途 | 文件名与更新规则 |
| --- | --- | --- |
| `学科/错题解析/` | 当天各份作业的错题解析与学习问答 | `YYYY-MM-DD.md`，**每学科每天一个文件**；同日新增来源合并到该文件 |
| `学科/周报分析/` | 一周的问题归纳、进步与行动清单 | `YYYY-MM-DD.md`，使用首次生成日期；正文标明覆盖区间，同一期更新原文件 |
| `学科/强化训练/` | 专项、月考、期中考、期末考训练及复测 | `YYYY-MM-DD-主题.md`；同日同主题更新原文件，独立批次加 `-第2组` 等清晰后缀 |

每日解析默认按**批改日期**归档，作业日期另记；用户指定归档日期时优先采用。训练使用首次生成日期。日期取任务发生时的实际日期，不写死某一天。

历史 `英语/错题周报/` 内容与链接保留，也可作为复习依据；不迁移、不据此补造不存在的每日解析。

## 默认输入与任务识别

**用户明确的任务、学科、日期区间和考试范围，优先于以下默认规则。**

| 用户输入 | 默认理解与执行 | 默认读取范围 |
| --- | --- | --- |
| 直接提供作业图片，未说明其他任务 | 检查作答、批改并解释错误，按学科归入当天错题解析 | 本次图片、当天已有记录及必要的相关历史 |
| “月考”或要求月考训练 | 根据当月薄弱点生成针对性训练 | 当月第一天至当天的错题解析、周报、训练与实际复测记录 |
| “期中考”或要求期中训练 | 根据本学期累计薄弱点生成针对性训练 | 本学期开学至当天，包含已过去月份和当月的相关记录 |
| “期末考”或要求期末训练 | 根据本学期累计薄弱点生成针对性训练 | 本学期开学至当天的相关记录 |
| 要求生成周报 | 汇总对应学科的一周学习情况 | 用户指定区间；未指定时为本周一至当天，并说明区间 |

- 非作业图片不强行按作业处理。没有孩子作答的题可以讲解，但须标记未作答，不能编造答案或判定掌握程度。
- 学科、学期起始日期优先采用用户明确提供的信息及已有可信记录；仍不明确且影响选材时，一次性询问必要信息，不擅自假设年级、教材或开学日期。
- 未提供学校考试范围时，可先生成**基于已归档错题的针对性训练**，明确它不代表完整考试范围；提供范围后再按范围筛选。
- 分析与训练须列明实际使用的日期区间、学科和资料来源，说明缺失月份或记录缺口；**没有记录不等于没有错误，更不等于已经掌握**。
- 同一错题按来源、日期、页码和题号关联去重，不能因为同时出现在日解析和周报中而重复计数。再次实际作答才是新的复测或出错事件。
- 按正文覆盖区间筛选周报，而非只看文件名；跨月、跨学期周报只使用可定位到目标时间范围的记录，不直接套用整周统计。历史仅有周报时注明证据来源与粒度限制。

## 使用示例

用户可直接用下列提示词发起试卷批改任务（附试卷图片）：

> 请使用 leo-study-assistant，将这份试卷交给 GLM 试卷批阅 子代理批改。先验证它能读取图片；可并发且题组独立时最多分成两个题组同时处理。你负责复核、汇总及按规范归档；无法调用或读取图片时说明原因并串行处理。

配套约定：

- 主代理先读取本 `README.md`，建立题目清单，按完整、独立的题组切分；子代理只回传结果，不写文件、不执行 Git。
- 示例中的并发是**条件性**的：先验证子代理能读取图片，确认可并发且题组独立后才分派，默认最多两个题组。
- 无法调用子代理、无法读取图片或图片不清时，主代理串行处理并说明原因；不猜测题干与学生作答，存疑题保留待核实。
- 复核、去重、归档、提交与推送由主代理统一完成；子代理回传只是待复核输入，不构成归档事实。

## 每日错题解析

同一天同一学科只维护一份文件。**写入前先读当天已有内容**，按练习来源分组，再按页码、题号追加或更新；不覆盖其他来源，不因重新识图重复记题。订正和复测追加日期及新结果，保留孩子原答案与原错误，不把历史改成“从未出错”。

### 内容模板

1. **当日概览** — 学科、批改日期、已检查的作业份数、确认错题数、未作答数、存疑数；统计范围不足时注明。
2. **来源信息** — 每份作业分别记录练习名称、页码、题号范围及已知的作业日期；未知信息标记未提供。
3. **逐题解析** — 每题记录下列字段，可按题分小节：
   - 定位信息与必要题干：来源、页码、题号，保留理解题目所需的条件。
   - 孩子原答案、正确答案及分步思路；开放题注明评价依据或参考答案，不把唯一表述当作唯一正确答案。
   - 知识点与错因规则：说明具体误用、漏掉的条件或思路问题，不只写正确答案，也不笼统归结为“粗心”；推测的错因标记待确认。
   - 订正与复测：待订正／已订正待复测／复测通过／复测未通过，并附实际发生日期、作答结果及关联训练链接；无结果时保持待处理状态。
4. **未作答与存疑题** — 未作答题单列并标记需补做，信息完整时提供参考答案；看不清、缺题干或有歧义的题保留原因和待核实事项，不猜测、不默认为答错，不因暂时无法核实而删除。
5. **做得好的题** — 记录有依据的进步、正确思路和良好习惯，给出具体正向反馈。
6. **概念问答** — 记录当日与学习有关的疑问及解释，关联题目；没有问答时注明无，不编造。
7. **当日重点** — 提炼需要订正、复习或复测的知识点，供周报与考前训练使用。

## 周报分析

周报首次生成时使用当天日期命名，正文明确覆盖的起止日期及实际资料范围；更新同一期时保留原文件名，并注明更新日期。仅在用户要求周报时生成，不随每次批改重复生成。

### 内容模板

1. **本周概览** — 日期区间、来源链接、批改份数、确认错题数、未作答数、存疑数、概念问答数及资料缺口。
2. **错题明细** — 按来源和知识点列出代表性问题，链接每日记录；重点是重复错因与变化，不整篇复制每日解析。
3. **做得好的题** — 结合实际订正、复测记录说明进步，不把没有新错题记录等同于掌握。
4. **概念问答整理** — 汇总词义、语法、解题方法等疑问与解答，关联来源。
5. **错误类型归纳** — 按根因和知识点归类（如近形词混淆、时态标志词、词性判断），统计独立错题或实际出错事件，并明确口径；区分已改善与仍反复出现的问题。
6. **下周行动清单** — 用可勾选任务列出补做、订正、专项练习和复测，说明对应知识点与检查方式。

确认错题、未作答、存疑分别统计；错误率只有在已检查题数等分母可确认时才计算。多标签分类须注明各类数量可能重叠，不将类别次数直接视为独立错题总数。资料不足时保留缺口，不补造历史记录或统计数字。

## 强化训练与考前复习

专项训练及月考、期中考、期末考训练均保存到对应学科 `强化训练/`。例如 `YYYY-MM-DD-月考专项.md`、`YYYY-MM-DD-期中考复习.md`。同日同主题追加或更新原文件；用户明确需要新一组题时使用独立批次后缀。

### 内容模板

1. **训练目标与资料范围** — 学科、任务类型、历史资料起止日期、已知考试范围及资料缺口；注明是否仅为已归档错题专项训练。
2. **问题依据** — 链接原始错题、周报和已有复测结果，列出待强化知识点及选择原因。
3. **分层题目** — 围绕基础巩固、同类变式和适当综合应用出题；难度与题量结合已知学习阶段及用户要求，未知年级、教材不擅自假设。
4. **独立答案解析区** — 与题目分开，逐题对应答案、思路及易错规则，方便孩子先独立完成。
5. **实际作答与复测结果** — 未收到作答时标记待完成／待复测；收到后记录日期、孩子答案、检查结果，并链接、更新对应每日记录。
6. **下一步建议** — 根据实际表现安排继续练习或间隔复测，不无限重复已证实改善的问题。

### 选题与掌握判断

- 先按默认输入规则或用户指定的学科、日期和考试范围筛选，再结合训练与复测记录判断；优先安排**反复出错、尚未订正、复测未通过**的知识点。
- 每道题或题组关联相应知识点及历史问题依据；以变式题检查规则能否迁移，不能只换顺序照抄原错题。
- 月考读取当月记录；期中考、期末考读取本学期开学至当天的累计记录，包含已过去月份及当月，不只看最近一周。
- 生成练习不等于完成练习，完成订正不等于已经掌握；答对一次也不自动代表稳定掌握。没有新结果时保留待复测状态，并保留此前复测未通过的事实。
- 若相关历史不足，先说明能覆盖的知识点和缺口；补充的通用巩固题须明确标注，不伪称来自孩子的历史错误。

核心原则：记录**错因规则和真实复测证据**，让复习有依据，而非只存答案或仅凭错题数量下结论。

## Agent 工作流程

1. **先读规范** — 在回答学习问题、识图批改、分析或出题前读取本 `README.md`；本轮已读且内容未变时可复用。先识别任务及适用范围，再读取对应学科的当天记录和必要历史，不每次扫描全部仓库。
2. **核对已有内容** — 记录任务开始时的工作区与暂存区状态；编辑前读取目标文件，保护用户已有修改及历史内容。缺少关键资料时集中询问，能够依据默认规则处理的内容不反复确认。
3. **处理与归档** — 用适合孩子理解的解释说明答案和方法，提供家长可执行的复习建议；按上述模板保存有价值的学习成果。学习概念问答可合并到当天记录；普通闲聊、操作确认不创建学习记录，也不擅自生成周报。
4. **保存前自查** — 核对题干、答案依据、错因证据、日期与来源链接；检查重复记录、统计口径和待核实项，确保对话结论与归档一致。存疑项不得在无依据时标成已解决。
5. **提交与上传** — 按下一节检查范围，只提交、推送本次授权成果；工具或环境要求授权时遵守授权流程，不绕过限制。
6. **如实交付** — 简述本次处理结果和需要家长确认的事项，列出文件路径；分别报告“已保存／未保存”“已提交／未提交”“已推送／未推送”。失败时说明原因，存在冲突记录时给出路径，不把本地保存当成上传成功。

## 自动提交、推送与冲突处理

用户约定：**正常完成需要归档的学习任务后，自动提交并推送本次成果，无需每次再次询问；用户明确要求暂不上传时除外。** 没有文件变化时不创建空提交。此约定不替代工具或执行环境的权限要求。

### 正常流程与提交边界

- 提交前检查工作区、暂存区、当前分支、实际远端和上游跟踪关系，并确认远端状态；不能仅凭过期的本地远端引用宣称已同步。
- 审阅具体差异，逐个指定本次授权文件或改动，避免全量暂存夹带无关内容。已有暂存改动、同文件内混杂的用户修改也必须识别；无法安全区分时暂停上传并说明，不丢弃或擅自回退。
- 推送前审阅全部待推送提交，不能因文件范围正确就顺带上传无关历史提交。只向已确认的对应远端分支推送，不擅自另建分支绕过问题。
- 提交说明概括学科、日期或训练主题；确认提交成功后再推送，确认推送结果后才能报告“已上传”。
- 不强制推送、不硬重置、不自动选择一方覆盖、不改 Git 配置、不跳过钩子。遇到无法安全处理的分支分歧或内容冲突即停止自动上传；不自动进行高风险合并或变基。

### 冲突文件

发生实际内容冲突时，在根目录创建 `冲突记录-YYYY-MM-DD-HHmmss.md`，使用发生时的日期与时间；重名时加 `-2` 等序号，不能覆盖已有记录。

冲突记录包含：

1. **发生时间与阶段** — 保存、提交、同步或推送阶段，以及真实错误信息。
2. **冲突类型** — 已确认的内容冲突，或“分支分歧／非快进，尚未确认内容冲突”，不可混淆。
3. **影响范围与版本** — 受影响文件路径（尚不能确认时注明）、本地分支、远端分支及可取得的版本标识；未提交内容另说明，不把提交版本当作它的备份。
4. **双方内容与保留方式** — 对文本记录必要冲突片段，明确本地／远端；注明双方完整内容可恢复的位置或 Git 版本。涉及未提交内容或 Git 未保存的数据时，保留原文件并提供必要副本，不能只记录版本号后覆盖原件。无法取得远端内容时注明未取得，不编造。
5. **当前状态与待处理事项** — 哪些成果已保存、已提交、未推送，哪些问题需要用户选择；不得将生成冲突报告称为冲突已解决。

- 遇分支分歧或非快进拒绝时也可生成同类记录，但必须明确是否真正检测到内容冲突；远端领先本身不等于文件内容冲突。
- 冲突发生后停止自动上传，保留双方可恢复内容；不得为上传报告而提交未解决的合并。冲突文件先保存在本地，待处理后再由用户决定如何提交。
- 网络中断、认证或权限失败应按真实原因报告并停止，不冒充内容冲突，不声称推送成功。没有冲突时不创建占位冲突文件。

## 隐私与维护边界

- 只归档必要的学习信息。默认不上传原始作业照片，尤其是包含学校、班级、联系方式、住址等信息的照片；记录和冲突报告也不复制无关个人信息、账号凭证或访问令牌。
- 不因仓库有远端就假定它是私有仓库。确需保存原图时先确认用户要求、去除非必要敏感信息，再按授权范围处理。
- 不修改 Git 配置，不删除 `.codebuddy/` 等项目数据，不擅自迁移、删除历史资料或补造记录。
- 本仓库使用 Markdown 和 Git 维护，不依赖额外数据库、定时任务或自动加载配置；`README.md` 由用户要求 agent 读取后执行。
